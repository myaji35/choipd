릴레이 GO(Gemini 10 / Codex 9, 평균 9.5) — 공개 페이지 방문 고객 루프 10회 뒤 이어 감.
목표: 처음 가입한 1인 전문가가 막힘 없이 가입하고, 승인 대기 동안 무엇을 할 수 있는지 알고, 승인 뒤 '누구·하는 일·연락'이 갖춰진 공개 페이지를 처음 공개하기까지의 클릭·막힘을 줄인다.
촬영: script/qa/onboarding_loop_shots.cjs (로컬 개발 DB 전용). 회차마다 새 시험 회원 ux-onb-<회차>-d/m@impd.test 를 이메일로 가입시키고 → 도착 화면 → 첫 화면의 편집류 링크 1회 클릭 → 대시보드·에디터 1단계·서비스 → 서비스 1개 등록 → 비로그인으로 공개 페이지 확인. 승인 대기 회원 ux-pending(id26, 비밀번호는 세션 한정 값)으로 로그인한 화면도 촬영.
측정: 가입 화면 보이는 입력 칸 수, 실제 클릭·입력 수, 막힌 화면(편집 길 없음·404·로그인 튕김), 공개 페이지 준비(서비스·문의 폼·문의 버튼), 콘솔 오류, 가로 넘침.
규칙: 인증·권한 규칙(승인 전 공개·편집 차단, fc5a45f)은 바꾸지 않는다. 실제 메일 발송·운영 DB·배포 없음.

## 시작 관찰 (Opus, r00)
- 이메일 가입은 바로 승인(approved) 상태로 만들어지고, Google 가입만 승인 대기(pending_approval)로 간다(MemberSignupsController signup_defaults, OmniauthCallbacksController).
- 가입 화면 보이는 입력 칸 15개(이름·이메일·비밀번호·확인·주소·직업 고르기·지역·동의 둘 등). 필수는 4칸 + 약관 동의.
- 가입 직후 도착 화면은 본인 공개 페이지(/<slug>). 첫 화면에 '편집'·'관리' 버튼이 없음 — PC 는 위 메뉴 '내 페이지'(누르면 같은 화면), 390 은 ☰ 뿐 → 390 막힘 1. 환영 안내('이제 페이지를 편집할 수 있어요')도 첫 화면에서 안 보임.
- 직업을 안 고르면 'custom' 으로 저장되어 공개 페이지에 '크리에이터'로 보임(회원이 고르지 않은 값).
- 승인 대기 회원이 로그인하면 홈(마케팅 화면)으로 가고, 첫 화면에 '승인 대기' 안내가 안 보이며 '내 페이지 만들기' 버튼이 크게 보임.
- 서비스 등록(제목만) 후 비로그인 공개 페이지에 서비스·문의 폼·문의 버튼 모두 보임(준비 완료 도달은 가능).
- 측정(직접 주소로 건너뛴 최소 경로): PC 클릭 4·입력 5, 390 클릭 3·입력 5 + 편집 길 못 찾음 1. 콘솔 오류: 대시보드·에디터·서비스 화면 1440 에서 각 1건.
