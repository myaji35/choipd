# imPD · SocialDoctors · Townin — 역할과 연동 (2026-11-19)

대표님 지시
- "impd는 프로필, 브랜드를 관리할거야. 브랜드는 socialDoctors 프로젝트를 이용해서 매체 및 컨텐츠 관리를 하고 싶어. 매체에는 Townin을 넣고 지역에 광고하는 기능을 구현하자. 1차 업종은 보험설계사를 샘플로 테스트 하면서 완성도를 올리자."
- "각 프로젝트의 역할을 분명히 하고 유기적인 운영을 기대할게."

## 1. 한 줄 역할

| 프로젝트 | 한 줄 역할 | 원본으로 가지는 것 | 하지 않는 것 |
|---|---|---|---|
| **imPD** (0008_choi-pd, Rails, impd.townin.net) | **사람과 브랜드의 원본** — 설계사가 자기 프로필·브랜드를 등록하고, 어디에 노출할지 **동의**하고, 결과를 한 화면에서 본다 | 회원 프로필, 브랜드(이름·업종·지역·소개·이미지), 노출·광고 동의, 외부 인물정보(네이버·LinkedIn) | 콘텐츠 제작·발행·광고 집행·과금 |
| **SocialDoctors** (0017, Next.js, app.socialdoctors.kr) | **브랜드 홍보 운영실** — 브랜드를 받아 콘텐츠를 만들고, 매체에 발행하고, 성과를 모으고, 청구한다 | 캠페인, 콘텐츠(카드뉴스·게시물), 매체(채널) 연결, 발행 기록, 성과 모음, 견적 | 회원 가입·프로필 원본·동의 수집, 지역 광고 노출·과금 |
| **Townin** (0014, NestJS, townin.net) | **지역 매체** — 동네 주민에게 디지털 전단지를 보여 주고, 읽은 사람 수로 과금한다 | 광고주(소사장) 계정·광고 포인트, 전단지, 노출 지역(H3·행정동), 읽음·클릭 기록, 파트너 승인 | 콘텐츠 기획, 다른 매체 발행, 브랜드 원본 |

판별 기준(SocialDoctors 몸통 한 줄 그대로): **브랜드를 등록하면(imPD) → 홍보 자산이 나오고(SD) → 채널에 발행되고(SD → SNS·Townin) → 성과가 보이고(Townin·SNS → SD → imPD) → 그 대가를 청구한다(SD 견적, Townin 광고 포인트).**

## 2. 데이터 흐름

```
[설계사] ──가입·프로필·브랜드·동의──▶ imPD
                                    │  GET /api/socialdoctors/consented-brands (X-Api-Key)
                                    ▼
                              SocialDoctors ──콘텐츠 제작──▶ 캠페인·카드뉴스
                                    │                     │
                                    │ SNS 발행(8종)        │ Townin 전단지 발행(신규)
                                    ▼                     ▼
                                 SNS 성과            Townin 연동 API (X-API-Key, 신규)
                                    │                 광고주 연결 → 전단지 → 지역 → 제출
                                    │                     │ 파트너 승인 → 주민 노출 → 읽음 1명당 50원
                                    ▼                     ▼
                              SocialDoctors 성과 모음 ◀── 읽음·클릭·사용 포인트
                                    │
                                    ▼  (성과 요약 조회)
                                  imPD "내 브랜드" 화면 — 설계사가 한 화면에서 확인
```

- **원본은 한 곳**: 브랜드 정보는 imPD에서만 고친다. SD·Townin은 받아서 쓴다. Townin 광고주 계정은 설계사 이메일로 연결한다(기존 imPD↔Townin `lookup-by-email` 계약 재사용).
- **동의가 문**: imPD에서 ① SocialDoctors 노출 동의(`socialdoctors_exposure`, SD 명세 그대로) ② Townin 지역 광고 동의(`townin_local_ads`, 신규)를 받은 브랜드만 흘러간다. 철회하면 다음 동기화 때 SD 발행·Townin 신규 전단지가 멈춘다.
- **Townin 전단지는 광고주 본인 명의로 나간다.** SD는 설계사의 동의를 받아 그 설계사 본인의 소사장 계정으로 전단지를 만들고 제출만 대신한다. Townin 파트너(지역 승인자)의 역할은 그대로다. 파트너는 "광고대행인이 아니다"라는 Townin 정의와 충돌하지 않는다.
- **돈의 흐름**: Townin 광고비는 설계사의 Townin 광고 포인트에서 차감(읽은 사람 1명당 50원, 공개 문구 "100원 이내"). SD 운영 대행비는 SD 캠페인 견적. 연동 개발 단계에서는 로컬 시드 포인트로만 시험하고 실결제는 하지 않는다.

## 3. 연동 계약

| # | 방향 | 엔드포인트 | 상태 |
|---|---|---|---|
| A | imPD → SD (사람 이동) | `GET {SD}/api/admin/handoff?…&sig=` HMAC(`IMPD_HANDOFF_SECRET`) | 있음 |
| B | SD ← imPD (브랜드 동기화) | `GET {imPD}/api/socialdoctors/consented-brands?since=` `X-Api-Key` — 명세 `0017/docs/impd-brand-consent-api-spec.md` | **imPD 미구현 → ISS-475** |
| C | imPD → Townin (회원 조회·파트너 승급) | `GET /users/lookup-by-email`, `PATCH /users/:id/upgrade-role` `X-API-Key` | 있음 |
| D | SD → Townin (지역 광고) | `/integrations/socialdoctors/*` — 광고주 연결, 전단지 생성·수정, 노출 지역(행정동 코드 → H3), 제출, 성과 조회 | **신규 → Townin ISS-722** |
| E | imPD ← SD (성과 요약) | `GET {SD}/api/brands/{externalId}/summary` `X-Api-Key` — 매체별 발행 수·최근 콘텐츠·Townin 읽음·사용 포인트 | **신규 → SD ISS-521** |

## 4. 1차 업종 — 보험설계사 샘플 여정 (완성도 판정 기준)

샘플 인물: **나설계**(가상, 보험설계사, 경기 성남시 분당구 정자동) — Townin 시드 `seed-impd-scenario.ts`의 인물과 같은 사람으로 맞춘다. 실존 인물·실제 고객 정보는 쓰지 않는다.

| 단계 | 어디서 | 하는 일 | 완료 기준 |
|---|---|---|---|
| 1 | imPD | 가입 → 직업 "보험설계사" → 프로필 작성 | 공개 페이지에 보험 모집인 표기가 보인다 |
| 2 | imPD | 브랜드 등록(이름·업종·지역·소개) | 브랜드 목록·상세에 보인다 |
| 3 | imPD | 동의 2종(SD 노출, Townin 지역 광고) | 동의·철회가 기록된다 |
| 4 | SD | 브랜드 동기화 | SD 브랜드 목록에 `source=impd`로 생긴다 |
| 5 | SD | 캠페인 → 카드뉴스 생성(보험 광고 심의 문구 포함) | 콘텐츠가 검토 대기에 오른다 |
| 6 | SD | 매체 선택: SNS + Townin(정자동·반경 1km) | 매체별 발행 예약이 생긴다 |
| 7 | SD → Townin | 전단지 생성·지역 지정·제출 | Townin에 `submitted` 전단지가 생긴다 |
| 8 | Townin | 파트너 승인 → 주민 노출 | `approved`, 미승인 상태에서는 과금 0 |
| 9 | Townin | 주민 읽음(시뮬레이션) | 읽은 사람 1명당 50P 차감 |
| 10 | SD | 성과 수집 | 캠페인 성과에 Townin 읽음·클릭·사용 포인트 |
| 11 | imPD | "내 브랜드" 화면 | 매체별 현황·Townin 성과를 한 화면에서 본다 |
| 12 | imPD | 동의 철회 | 다음 동기화 후 SD 발행·Townin 신규 전단지 중단 |

## 5. "운영 수준 95%" 판정
- 위 12단계 × 화면 기준 5개(첫 화면에서 다음 할 일이 보이는가 / 빈 상태 안내 / 오류·로딩 안내 / 휴대폰 너비에서 쓸 수 있는가 / 용어가 설계사 말로 되어 있는가) = 60칸.
- 통과 칸 ÷ 60 ≥ 95%(57칸)일 때 "운영 수준 95%"로 본다. 칸별 판정은 화면 캡처와 함께 `docs/ecosystem-ux-scorecard.md`에 기록한다.

## 7. 대표님 확인이 필요한 것(모아서 컨펌 문서로)
- 세 프로젝트 운영 배포(모두 `main` push = 운영 배포). 개발·검증은 로컬에서 끝까지 한다.
- SocialDoctors 운영 서버 장애(SD ISS-446, 도메인 NXDOMAIN·서버 무응답) — 배포 전에 풀려야 한다.
- Townin ISS-698(미승인 전단지 과금 차단) 배포 — 이 연동의 전제.
